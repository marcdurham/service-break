UX Improvement: Removing the "Permission Wall"

Problem: The current onboarding requires immediate location permission to proceed. Users are highly likely to deny permissions when faced with an unexpected system prompt, leading to a broken or empty experience.

Solution: Implement a "Browse without Location" fallback. Allow users to explore the app using a default city (e. e.g., Seattle) or search for a different location before prompting for GPS access.

Proposed Flow

  1. Landing: Show the same beautiful onboarding, but with two buttons: "Enable Location & Explore" (Primary) and "Explore Seattle" (Secondary).
  2. Low Friction: If they click "Explore Seattle", load the map at FALLBACK_CENTER without triggering a browser permission dialog.
  3. Value First: Once the user sees how great the app is, use a subtle UI prompt later (e.g., a banner on the map) to suggest enabling location for better accuracy.
